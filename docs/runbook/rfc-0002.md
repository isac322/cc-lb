# RFC-0002 — Event-driven Lifecycle Runbook

Post-migration operational reference for the RFC-0002 event-driven
lifecycle. Superseded predecessors: `docs/runbook/lifecycle-shadow.md`
(kept for historical rollout context).

## Architecture in one paragraph

The proxy request handler emits `LifecycleEvent`s (defined in the
`cc-lb-lifecycle` crate) via `LifecycleContext::emit_lifecycle`. The
`InMemoryBus` fans events out to bounded per-subscriber mpsc channels,
each drop-newest on overflow. The `RequestEventAssembler` is the sole
writer of `request_events_v1` rows; on `RequestTerminated` it finalises
a partial and republishes the row to the admin SSE broadcast. Per-concern
subscribers (pricing, cache observation, limit reconcile, hook adapter,
rate-limit header, subscription quota, limit rejection audit, api-key
metrics, cache hit/miss, prompt-cache drift) consume the same event
stream independently.

## Configuration

Each subscriber is toggled by
`config.lifecycle_<name>_subscriber.enabled` (default `true` on the
canonical config from Phase 6). Toggling to `false` disables the
subscriber's mpsc attach + spawn; the assembler is not toggleable.

```toml
# All defaults after Phase 6/13:
[lifecycle_pricing_subscriber]           # enabled = true
[lifecycle_limit_reconcile_subscriber]   # enabled = true
[lifecycle_cache_observation_subscriber] # enabled = true
[lifecycle_hook_adapter_subscriber]      # enabled = true
[lifecycle_rate_limit_header_subscriber] # enabled = true
[lifecycle_subscription_quota_subscriber]      # enabled = true
[lifecycle_limit_rejection_audit_subscriber]   # enabled = true
[lifecycle_api_key_metrics_subscriber]         # enabled = true
[lifecycle_cache_hit_miss_subscriber]          # enabled = true
[lifecycle_prompt_cache_drift_subscriber]      # enabled = true
```

`request_event_writer_source` is gone. The assembler is the only writer
path; there is no rollback config knob.

## Metrics

### Assembler

- `cc_lb_lifecycle_assembler_rows_total{outcome="written"}` — row
  persisted (happy path).
- `cc_lb_lifecycle_assembler_rows_total{outcome="written_orphan"}` —
  row persisted for a `RequestTerminated` that had no prior
  `RequestStarted` (short-circuit before parse — e.g. body-too-large).
- `cc_lb_lifecycle_assembler_rows_total{outcome="terminated_without_partial"}`
  — terminated without a matching partial; row skipped. Nonzero in
  steady state suggests an event-loss or ordering bug.
- `cc_lb_lifecycle_assembler_rows_total{outcome="orphan_ttl_evicted"}`
  — partial sat in the map longer than 300s. Expected zero in steady
  state; nonzero suggests a missing terminator path.
- `cc_lb_lifecycle_assembler_rows_total{outcome="cap_evicted"}` — map
  exceeded 4096 in-flight partials, oldest dropped. Nonzero indicates
  either a real load spike or a leak.
- `cc_lb_lifecycle_assembler_storage_error` — assembler could not
  persist (DB down, migration missing).

### Subscribers

Each subscriber emits `cc_lb_lifecycle_<name>_events_total{outcome=...}`
with outcomes:

- `observed` — event handled successfully.
- `terminated_without_partial` — analogous to the assembler outcome.
- `orphan_ttl_evicted` / `cap_evicted` — same semantics as the
  assembler.
- Subscriber-specific `skipped_*` outcomes (e.g. `skipped_non_success`,
  `skipped_no_usage` for limit_reconcile) capture no-op cases that are
  expected in normal traffic.

### Bus backpressure

Each channel has a drop counter under
`cc_lb_dropped_events_total{reason="lifecycle_<channel>_full"}`.
Channels:

- `lifecycle_assembler_full`
- `lifecycle_hook_adapter_full`
- `lifecycle_pricing_full`
- `lifecycle_limit_reconcile_full`
- `lifecycle_cache_obs_full`
- `lifecycle_rate_limit_header_full`
- `lifecycle_subscription_quota_full`
- `lifecycle_limit_rejection_audit_full`
- `lifecycle_api_key_metrics_full`
- `lifecycle_cache_hit_miss_full`
- `lifecycle_prompt_cache_drift_full`
- `lifecycle_aggregator_full` (reserved for future admin SSE
  aggregator; currently unused)

Any nonzero rate is a real event loss.

### Cache observations dropped

`cc_lb_cache_observations_dropped_total{reason=...}` with reasons:

- `context_missing_upstream` / `context_missing_route` — cache
  observation context could not be built. Fires from inside the
  prompt-cache pipeline, not observable from lifecycle events — remains
  inline in the handler.
- `status_4xx` / `abort` — client-error or stream-abort cases.

## Sanity queries

Row-count sanity — how many rows the assembler wrote in the last hour
vs how many terminated requests hit the handler:

```sql
SELECT COUNT(*) FROM request_events_v1
WHERE ts >= strftime('%s', 'now', '-1 hour');
```

Every row now carries `event_id = <fresh v7 uuid>`. The assembler is the
only writer, so every `request_events_v1` row is assembler-written and no
legacy-vs-assembler correlation column remains.

## Rollback

There is no in-config rollback for the assembler-only architecture.
Rolling back means reverting the branch. The last known-good
pre-migration commit is `070c9614` (`H4 - remove handler inline
limit_engine.reconcile()`).

## Verification suite

The end-to-end verification lives in
`crates/cc-lb-server/tests/rfc_0002_fix_live_qa.rs`:

- `live_qa_1_default_boot_happy_path_writes_row_and_reconciles` — boots
   the server, POSTs one message, asserts exactly one row lands with
  `event_id IS NOT NULL`.
- `live_qa_2_oauth_usage_does_not_produce_request_event_row` — proxy
  bypass paths do not write rows.
- `live_qa_3_unknown_route_and_method_not_allowed_do_not_write_row` —
  404/405 do not write rows.
- `live_qa_6b_assembler_populates_cost_cache_usage_fields` —
  non-stream happy path populates cost, cache_state, usage, and the 12
  previously-missing timing/token fields.
- `live_qa_6c_assembler_populates_stream_fields` — streaming
  happy path populates stream-specific fields (`body_bytes`,
  `stream_message_start_ms`, `stream_total_ms`, `sse_event_count`, and
  usage/cost).

Run:

```
cargo test -p cc-lb-server --features sqlite \
  --test rfc_0002_fix_live_qa -- --test-threads=1
```
