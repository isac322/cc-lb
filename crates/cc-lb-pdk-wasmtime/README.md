# cc-lb-pdk-wasmtime

`cc-lb-pdk-wasmtime` is the guest-side Plugin Development Kit for cc-lb wasm
plugins running under wasmtime. It provides allocator exports, hook dispatch
helpers, macro re-exports, and access to the shared wire types.

Most plugin authors depend on this crate and write plain Rust handler
functions. The macros generate the ABI glue around those functions.

## What This Crate Provides

- Re-exports for `#[cc_lb_plugin]` and `#[handler]`.
- A `types` re-export of `cc-lb-plugin-wire`.
- Guest-side `cc_lb_alloc` and `cc_lb_free` exports generated by the plugin
  macro.
- Hook dispatch helpers for owned and archived-view request modes.
- A `wasm32-unknown-unknown` global allocator based on `dlmalloc`.
- A wasm panic handler that traps so the host can discard the failed store.

## Global Allocator Setup

The `wasm32-unknown-unknown` target does not provide a default allocator. This
crate installs `dlmalloc::GlobalDlmalloc` for wasm32 builds so plugin crates do
not need allocator boilerplate.

```toml
[lib]
crate-type = ["cdylib"]

[dependencies]
cc-lb-pdk-wasmtime = "0.1"
cc-lb-plugin-wire = "0.8"
```

Do not declare another global allocator in the same plugin unless you intend to
own all guest allocation behavior.

## ABI Notes

The host and generated guest code use a small C ABI surface:

- `cc_lb_alloc(size, align) -> ptr`
- `cc_lb_free(ptr, size, align)`
- `cc_lb_filter(in_ptr, in_len) -> packed_u64`
- `cc_lb_shape(in_ptr, in_len) -> packed_u64`

Hooks return `(out_ptr, out_len)` packed into a `u64` as
`(ptr << 32) | len`.

## Typical Usage

Application code usually imports the macros and wire types, not the private
dispatch helpers.

```rust
#![cfg_attr(target_arch = "wasm32", no_std)]

extern crate alloc;

use alloc::boxed::Box;
use alloc::vec::Vec;
use cc_lb_pdk_wasmtime::{cc_lb_plugin, handler};
use cc_lb_plugin_wire::v1::{FilterRequest, FilterResponse, PerCandidateReason};

#[cc_lb_plugin(
    name = "accept-all",
    version = "0.1.0",
    description = "Accepts every upstream candidate.",
    usage = "Use as a smoke-test filter plugin.",
)]
mod accept_all {
    use super::*;

    #[handler(
        filter,
        wire = 1,
        description = "Accepts all candidates.",
        usage = "No configuration required.",
    )]
    pub fn filter(req: FilterRequest) -> FilterResponse {
        let results = req
            .candidates
            .into_vec()
            .into_iter()
            .map(|candidate| PerCandidateReason {
                upstream_id: candidate.upstream_id,
                decision: Box::from("accept"),
                reason: Box::from(""),
            })
            .collect::<Vec<_>>()
            .into_boxed_slice();
        FilterResponse { results }
    }
}
```

The host keeps a candidate only when `decision` is `"accept"`. Every candidate
absent from `results` is rejected, so an empty `results` rejects the whole set.

Filter handlers also receive the requested service tier on the V1 request as
`FilterRequest.service_tier`, an `Option<Box<str>>`. `service_tier` is the
optional tier requested in the inbound request body; a pre-request filter
cannot observe the tier ultimately reported by an upstream response. For a
tier-aware filter handler, see the filter example in the [plugin author
guide](https://github.com/isac322/cc-lb/blob/master/docs/plugin-author-guide.md#hook-contracts).
